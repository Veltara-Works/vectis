## B.1 Overview

All tables use UUIDs as primary keys — specifically UUIDv7 (time-sortable) for index performance. UUIDs are generated by the Go application, not by Postgres sequences. This ensures future clustering compatibility (no auto-increment conflicts across nodes).

All timestamps are `TIMESTAMPTZ` stored in UTC.

The schema is designed with the hybrid source-of-truth model in mind:
- **Postgres** stores operational entities (domains, mailboxes, aliases, admins, sessions)
- **config.yaml** stores infrastructure policy (global settings, resource profiles, TLS config)
- **secrets.yaml** stores sensitive values (passwords, keys, tokens)

## B.2 domains

Domains are stored in Postgres (not config.yaml) because they are operational entities that admins create and manage through normal operation. This simplifies the config engine and means Postfix/Dovecot can query domains via live SQL lookup without requiring config file regeneration.

```sql
CREATE TABLE domains (
    id              UUID PRIMARY KEY,
    name            VARCHAR(255) NOT NULL UNIQUE,
    active          BOOLEAN NOT NULL DEFAULT true,
    dkim_enabled    BOOLEAN NOT NULL DEFAULT true,
    dkim_selector   VARCHAR(63) NOT NULL DEFAULT 'default',
    dkim_key_path   VARCHAR(500),                          -- path to private key file, NULL if not yet generated
    spam_threshold  DECIMAL(4,1) NOT NULL DEFAULT 15.0,    -- Rspamd score threshold (overrides global default)
    max_mailboxes   INTEGER,                               -- NULL = unlimited
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_domains_name ON domains(name);
```

### Notes

- `dkim_selector`: Recommended convention is date-based (e.g., `202603`) for clean rotation with overlapping validity periods. Default `default` for initial setup simplicity.
- `dkim_key_path`: Points to private key file under `/var/vectis/dkim/<domain>/`. NULL means DKIM keys have not been generated yet.
- `spam_threshold`: Per-domain override. Global default is in config.yaml. Per-domain value takes precedence.
- `max_mailboxes`: NULL = unlimited. Useful for hosting providers or licence-based limits.

## B.3 mailboxes

```sql
CREATE TABLE mailboxes (
    id              UUID PRIMARY KEY,
    domain_id       UUID NOT NULL REFERENCES domains(id) ON DELETE RESTRICT,
    local_part      VARCHAR(64) NOT NULL,              -- the part before @
    password_hash   TEXT NOT NULL,                      -- Argon2id hash
    display_name    VARCHAR(255),
    quota_mb        INTEGER NOT NULL DEFAULT 1024,      -- mailbox quota in MB
    active          BOOLEAN NOT NULL DEFAULT true,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    UNIQUE (domain_id, local_part)
);

CREATE INDEX idx_mailboxes_domain ON mailboxes(domain_id);
CREATE INDEX idx_mailboxes_email ON mailboxes(domain_id, local_part);
```

### Notes

- `ON DELETE RESTRICT` on `domain_id`: Prevents accidental deletion of a domain that still has mailboxes. Admin must delete mailboxes first.
- `password_hash`: Argon2id with parameters: memory=65536 KB, iterations=3, parallelism=4. Stored in PHC string format (e.g., `$argon2id$v=19$m=65536,t=3,p=4$salt$hash`).
- `quota_mb`: Enforced by Dovecot via the userdb query (quota_rule returned in SQL lookup).
- The `(domain_id, local_part)` unique constraint ensures one mailbox per email address.
- Full email address is computed as `local_part || '@' || domain.name` — never stored redundantly.

## B.4 aliases

```sql
CREATE TABLE aliases (
    id                  UUID PRIMARY KEY,
    domain_id           UUID NOT NULL REFERENCES domains(id) ON DELETE RESTRICT,
    source_local_part   VARCHAR(64) NOT NULL,      -- empty string = catch-all
    destination         TEXT NOT NULL,              -- single address or comma-separated list
    active              BOOLEAN NOT NULL DEFAULT true,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    UNIQUE (domain_id, source_local_part)
);

CREATE INDEX idx_aliases_domain ON aliases(domain_id);
```

### Notes

- `source_local_part = ''` (empty string) creates a catch-all alias for the domain.
- `destination` can be:
  - A single external address: `forward@otherdomain.com`
  - A local mailbox: `user@same-domain.com`
  - Multiple addresses (comma-separated): `user1@a.com,user2@b.com`
- An alias cannot point to another alias (no chaining). The API validates this on creation.
- `ON DELETE RESTRICT` on `domain_id`: Same as mailboxes — prevent accidental domain deletion.

## B.5 admins

```sql
CREATE TABLE admins (
    id              UUID PRIMARY KEY,
    email           VARCHAR(255) NOT NULL UNIQUE,
    password_hash   TEXT NOT NULL,                  -- Argon2id
    totp_secret     TEXT,                           -- encrypted; NULL = TOTP not enabled
    totp_enabled    BOOLEAN NOT NULL DEFAULT false,
    role            VARCHAR(20) NOT NULL DEFAULT 'admin',  -- future: super_admin, domain_admin
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_login_at   TIMESTAMPTZ
);
```

### Notes

- `totp_secret`: Encrypted at rest using a key derived from the API secret in secrets.yaml. NULL means TOTP is not configured. If `totp_secret` is set but `totp_enabled` is false, enrolment was started but not completed.
- `role`: For Phase 1, only `admin` exists (full access). Phase 2 introduces `domain_admin` (scoped to specific domains) and `super_admin` (can manage other admins).
- `last_login_at`: Updated on each successful authentication. Used in the admin listing UI.
- The installer creates the first admin account during `vectis install`.

## B.6 sessions

Sessions are dual-stored:
- **Valkey:** For fast session lookup during request authentication (key = session ID, value = admin_id + expiry)
- **Postgres:** For session inventory and management UI (list active sessions, revoke sessions)

Valkey is the authority for session validity (if the Valkey key doesn't exist, the session is invalid). Postgres is the authority for session inventory (list all sessions for an admin).

```sql
CREATE TABLE sessions (
    id              UUID PRIMARY KEY,               -- also the Valkey key
    admin_id        UUID NOT NULL REFERENCES admins(id) ON DELETE CASCADE,
    token_hash      TEXT NOT NULL,                   -- SHA-256 of the session token
    ip_address      INET,
    user_agent      TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at      TIMESTAMPTZ NOT NULL
);

CREATE INDEX idx_sessions_admin ON sessions(admin_id);
CREATE INDEX idx_sessions_expires ON sessions(expires_at);
```

### Notes

- `ON DELETE CASCADE` on `admin_id`: Deleting an admin automatically removes their sessions.
- `token_hash`: The actual session token is only sent to the client (in the cookie). The server stores only the SHA-256 hash. This means a database leak doesn't directly expose session tokens.
- A background task (or Valkey TTL) cleans up expired sessions. Postgres rows are cleaned by a periodic sweep.
- `logout-all` operation: Delete all Valkey keys for the admin + delete all Postgres rows for the admin.

## B.7 orchestrator_history

```sql
CREATE TABLE orchestrator_history (
    id                  UUID PRIMARY KEY,
    action              VARCHAR(20) NOT NULL,          -- plan, apply, rollback
    status              VARCHAR(20) NOT NULL,          -- pending, running, completed, failed, rolled_back
    config_hash         VARCHAR(64) NOT NULL,          -- SHA-256 of config.yaml at time of action
    plan_summary        JSONB,                         -- structured diff of planned changes
    snapshot_path       VARCHAR(500),                  -- path to pg_dump file (for apply/rollback)
    container_versions  JSONB,                         -- { "postfix": "1.3.0", "dovecot": "1.2.1", ... }
    error_message       TEXT,                          -- populated if status = failed
    started_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    completed_at        TIMESTAMPTZ,
    triggered_by        UUID REFERENCES admins(id) ON DELETE SET NULL  -- NULL if triggered by CLI
);

CREATE INDEX idx_orch_history_started ON orchestrator_history(started_at DESC);
```

### Notes

- `plan_summary` JSONB example:

```json
{
  "container_changes": [
    { "service": "postfix", "from": "1.2.0", "to": "1.3.0" },
    { "service": "rspamd", "from": "3.8.0", "to": "3.9.0" }
  ],
  "config_changes": [
    { "file": "postfix/main.cf", "action": "modified" }
  ],
  "db_migrations": [
    { "id": "042_add_quota_tracking", "destructive": false }
  ]
}
```

- `snapshot_path`: Points to the pg_dump file created before an apply operation. Used by rollback.
- `container_versions`: Snapshot of all container image tags at the time of the operation. Used by rollback to know which versions to revert to.
- `ON DELETE SET NULL` on `triggered_by`: If an admin is deleted, the history entry remains but the triggering admin is anonymised.

## B.8 audit_log

Every mutating API call is logged. This table grows indefinitely; a retention policy (Phase 2) will archive or prune old entries.

```sql
CREATE TABLE audit_log (
    id              UUID PRIMARY KEY,
    admin_id        UUID REFERENCES admins(id) ON DELETE SET NULL,  -- NULL if CLI or system action
    action          VARCHAR(50) NOT NULL,              -- e.g. domain.create, mailbox.delete, config.apply
    resource_type   VARCHAR(30) NOT NULL,              -- domain, mailbox, alias, config, orchestrator
    resource_id     UUID,                              -- ID of affected resource (NULL for system actions)
    details         JSONB,                             -- changed fields, before/after values
    ip_address      INET,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_audit_created ON audit_log(created_at DESC);
CREATE INDEX idx_audit_admin ON audit_log(admin_id, created_at DESC);
CREATE INDEX idx_audit_resource ON audit_log(resource_type, resource_id);
```

### Audit log conventions

- `action` follows the pattern `resource.verb`: `domain.create`, `domain.delete`, `mailbox.update`, `config.apply`, `orchestrator.apply`, `auth.login`, `auth.logout`
- `details` captures what changed:

```json
{
  "before": { "quota_mb": 1024 },
  "after": { "quota_mb": 2048 }
}
```

- For `auth.login` events, `details` includes `{ "success": true/false, "ip": "...", "totp_used": true/false }`
- For creation events, `details` includes the full created object (minus password hashes)
- For deletion events, `details` includes the full deleted object (for audit recovery)

## B.9 backup_jobs (Phase 1)

Tracks async backup and restore operations. Created in migration `000002_phase1.up.sql`.

```sql
CREATE TABLE backup_jobs (
    id              UUID PRIMARY KEY,
    action          VARCHAR(20) NOT NULL,          -- 'create' or 'restore'
    status          VARCHAR(20) NOT NULL,          -- 'pending', 'running', 'completed', 'failed'
    backup_path     VARCHAR(500),                  -- path to backup archive
    progress        INTEGER NOT NULL DEFAULT 0,    -- percentage 0-100
    current_step    VARCHAR(100),                  -- e.g. "Dumping database", "Copying mail data"
    error_message   TEXT,
    started_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    completed_at    TIMESTAMPTZ,
    triggered_by    UUID REFERENCES admins(id) ON DELETE SET NULL
);

CREATE INDEX idx_backup_jobs_started ON backup_jobs(started_at DESC);
```

### Notes

- `action`: Either `create` (backup) or `restore`. Tracks the type of operation.
- `progress`: Integer 0–100 updated as each backup step completes. Clients poll `GET /backup/status/:jobId` for progress.
- `current_step`: Human-readable description of the current phase (e.g., "Dumping database", "Archiving mail data").
- `triggered_by`: NULL if triggered by CLI or scheduled backup; admin UUID if triggered via API.

## B.10 alert_history (Phase 1)

Tracks sent alerts for deduplication. The monitor checks this table before sending alerts to avoid repeated notifications.

```sql
CREATE TABLE alert_history (
    id              UUID PRIMARY KEY,
    severity        VARCHAR(20) NOT NULL,          -- 'info', 'warn', 'error', 'critical'
    service         VARCHAR(30) NOT NULL,          -- service name or 'system'
    message         TEXT NOT NULL,
    dedup_key       VARCHAR(255) NOT NULL,         -- key for deduplication (e.g. "postfix:unhealthy")
    sent_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    resolved_at     TIMESTAMPTZ                    -- NULL = still active
);

CREATE INDEX idx_alert_history_dedup ON alert_history(dedup_key, sent_at DESC);
CREATE INDEX idx_alert_history_active ON alert_history(resolved_at) WHERE resolved_at IS NULL;
```

### Notes

- `dedup_key`: Combination of service + severity (e.g., `postfix:error`). Same dedup_key won't be sent within the 15-minute dedup window.
- `resolved_at`: NULL while the alert condition is active. Set when the condition clears, triggering a recovery notification.
- Partial index `idx_alert_history_active` filters only unresolved alerts for fast lookup.
- CRITICAL severity alerts bypass deduplication and are always sent immediately.

## B.11 validonx_cache (Phase 1)

Caches ValidonX license entitlements for the 30-day grace period when the ValidonX API is unreachable.

```sql
CREATE TABLE validonx_cache (
    id              UUID PRIMARY KEY,
    tenant_id       VARCHAR(255) NOT NULL,
    subscription_id VARCHAR(255),
    license_data    JSONB NOT NULL,                -- cached license resolve response
    features        JSONB,                         -- cached feature flags
    status          VARCHAR(30) NOT NULL,          -- 'active', 'trialing', 'paused', 'canceled'
    last_check_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at      TIMESTAMPTZ NOT NULL,          -- grace period expiry
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX idx_validonx_cache_tenant ON validonx_cache(tenant_id);
```

### Notes

- `tenant_id`: Unique per installation. One cache row per Vectis instance.
- `license_data`: Full JSON response from `POST /v1/licensing/resolve`, cached for offline use.
- `features`: Cached feature flags (e.g., `{"custom_branding": true, "advanced_spam": true}`).
- `expires_at`: 30 days from `last_check_at`. After expiry, the system falls back to free-tier features.
- `status`: Mirrors the subscription state from ValidonX (active, trialing, paused, canceled).

## B.13 Schema Conventions Summary

| Convention | Decision | Rationale |
|------------|----------|-----------|
| Primary keys | UUIDv7 (time-sortable) | Clustering-safe, no sequence conflicts |
| UUID generation | Application (Go), not Postgres | Consistent across future cluster nodes |
| Timestamps | TIMESTAMPTZ (UTC) | Unambiguous across timezones |
| Soft delete | Not used (Phase 1) | Simplicity; audit_log captures deletion details |
| FK on domain delete | RESTRICT | Prevent accidental cascading data loss |
| FK on admin delete | SET NULL or CASCADE | Sessions cascade; audit/history anonymise |
| Password hashing | Argon2id (m=64MB, t=3, p=4) | Current best practice for password storage |
| Indexes | On foreign keys + common query patterns | Prevent full table scans on joins and filters |
| Migration tool | To be decided (golang-migrate recommended) | Forward-only migrations with version tracking |
